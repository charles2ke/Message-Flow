# Support

MessageFlow is maintained on a best-effort basis by volunteers. There is no commercial support
offering and no response-time commitment, except for security reports, which follow the targets in
[SECURITY.md](SECURITY.md).

## Where to go

| You want to | Use |
| --- | --- |
| Understand the API | the [README](README.md) and the per-port READMEs in `java/`, `python/`, `node/` |
| Try the library without installing it | the [playground](https://charles2ke.github.io/Message-Flow/) |
| Report a bug | a [bug report issue](https://github.com/charles2ke/Message-Flow/issues/new/choose) |
| Request a feature | a [feature request issue](https://github.com/charles2ke/Message-Flow/issues/new/choose) |
| Ask how to do something | a [question issue](https://github.com/charles2ke/Message-Flow/issues/new/choose) |
| Complete a security or procurement review | [ENTERPRISE.md](ENTERPRISE.md) |
| Report a vulnerability | a [private advisory](https://github.com/charles2ke/Message-Flow/security/advisories/new), never a public issue |
| Contribute a change | [CONTRIBUTING.md](CONTRIBUTING.md) |

## Getting a useful answer quickly

Include the port and version you use, the runtime version, a minimal chain that reproduces the
behaviour, what you expected and what happened instead. Issues without a reproducer usually stall.

## Supported versions

Only the latest patch of the current minor release receives fixes; see the support matrix in
[SECURITY.md](SECURITY.md). Questions about versions outside that window will be answered with an
upgrade path rather than a backport.
